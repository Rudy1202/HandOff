# 已有项目扫描指引（Path A 开始前必读）

## 目标

在不修改任何源码的前提下，产出准确的 `.codebuddy/CODEBUDDY.md`，让第二个工具开箱即有上下文。

## 扫描清单（全程只读）

1. **权威文档**：`README*`（含 `.zh.md`）、`document*/`、`docs*/`、`User-Manual*` — 完整逻辑、构建说明、仪器/设备支持表。
2. **清单文件**：`*.sln`、`*.csproj`、`package.json`、`pyproject.toml`、`go.mod`、`Cargo.toml`、`pom.xml`、`requirements*.txt` — 技术栈、目标框架、钉死的依赖版本。
3. **顶层目录树**（2 层即可，排除 `bin/`、`obj/`、`node_modules/`、`.git/`、`.vs/`）— 画关键路径表。
4. **.gitignore** — 确认没有忽略 `.codebuddy/`；若被忽略，提醒用户去掉该规则再提交。
5. **坑点线索**：在源码/文档中搜索 `TODO|FIXME|XXX|HACK|do not|勿|必须|钉死|pinned|verified|UNVERIFIED|quirk` 等字样，提取设备怪癖、环境约束、未验证路径。
6. **LICENSE** — 是否专有/需激活（影响发布与工具外置，如密钥生成器必须留在源码树外）。

## 输出到 CODEBUDDY.md 的内容

- **项目简介**：1–3 句（是什么、给谁用、专有还是开源）。
- **技术栈表**：含钉死版本与位宽/环境约束。
- **构建与运行**：build/run/test 命令 + 红线。
- **关键路径表**：10–20 行，每行「路径 → 角色」；只列另一个工具需要知道的，穷举每个文件没有意义。
- **核心架构要点**：3–7 条，每条指向权威文档章节（如「README §6」），**不要大抄原文**，避免两处维护漂移。
- **已知坑点**：编号列表，从 README/注释提取。
- **文档同步规矩**：用户可见文案改动要同步哪些文档、是否需要重新生成。

## 红线

- 全程只读源码；**只允许新增 `.codebuddy/` 下的文件**，不得修改/删除/移动任何既有文件。
- 项目已有 `.codebuddy/CODEBUDDY.md` 时：先读旧文件，在保留原有内容基础上补充更新，**绝不覆盖**。
- 已有 `.codebuddy/plans/` 历史计划可读取，用于还原「进行中的工作」。
- 验证：git 仓库执行 `git status --short`，确认只有 `.codebuddy/` 新增；工作区预存在的 `M`/`D` 条目原样告知用户，声明非本次改动。
- 用户明确说过「不要动源码」类红线时，把该红线写进生成的 `rules/project-rules.md`。
